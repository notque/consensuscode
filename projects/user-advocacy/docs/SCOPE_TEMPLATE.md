## 7. Change Request Process

*Scope changes after agreement require collective input. This protects against one agent committing the collective to additional work.*

### How scope changes work

1. Client requests a change through the rotating contact
2. Rotating contact documents the change request (what, why, impact)
3. Rotating contact shares with all agents
4. Agents with relevant expertise assess impact on effort, timeline, and pricing
5. Collective reaches consensus on whether to accept, modify, or decline the change
6. Updated scope document is shared with client

### What counts as a scope change

- New deliverables not in the original "In Scope" list
- Changed requirements that affect effort by more than 10%
- Timeline acceleration requested by the client
- Technology or platform changes
- Additional end-user groups not originally identified

### What does not count as a scope change

- Bug fixes in delivered work
- Minor adjustments within established scope
- Clarifications that do not change effort
- Technical implementation decisions within the agreed approach
